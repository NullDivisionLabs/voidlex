## Сборки

Релиз `1.1.8-beta` собирается из `C:\Projects\VoidLex-Release`.
Два отдельных APK для ARM64 и ARMv7:

```powershell
flutter build apk --release --target-platform android-arm64,android-arm --split-per-abi
```

Альфа собирается из `codex/alpha-xdrive` с Gradle-свойством `alpha=true`.
Например, для ARM64 в PowerShell:

```powershell
$previousAlpha = $env:ORG_GRADLE_PROJECT_alpha
try {
    $env:ORG_GRADLE_PROJECT_alpha = 'true'
    flutter build apk --release --target-platform android-arm64
} finally {
    $env:ORG_GRADLE_PROJECT_alpha = $previousAlpha
}
```

| Параметр | Релизная папка | Альфа с `alpha=true` (при разделении 28 сентября) |
| --- | --- | --- |
| Название | `Void//Lex` | `Void//Lex Alpha` |
| Android applicationId | `com.voidlex.voidlex` | `com.voidlex.voidlex.alpha` |
| versionName | `1.1.8-beta` | `1.1.7-beta-alpha` |

Без `alpha=true` альфа-ветка использует обычный applicationId: такой APK
нельзя выдавать за стандартную сборку. Оба варианта используют общие исходники
внутри своей ветки; отдельные Android product flavors не заведены.

## Ограничение xdrive

Следующие сведения описывают состояние при разделении 28 сентября.
В релиз `1.1.8-beta` изменения альфа-ветки не включены.

В альфе добавлен код интеграции xdrive, но отслеживаемые `libxray.so` для всех
трёх ABI совпадают со стандартной версией Xray-core `26.7.28`.
Работоспособность xdrive в поставляемом ядре не подтверждена. До выпуска
работающей альфы нужно поставить ядро с поддержкой xdrive, обновить сведения
о происхождении и контрольные суммы, затем проверить реальное подключение.
