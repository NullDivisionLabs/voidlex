# Редактор нод и URL-pingtest

Изменения разработаны в `codex/node-editor-urltest` и включены в стандартную
`main` коммитом `e82ed3b`. 1 октября 2026 года они перенесены в
`VoidLex-Release` для релиза `1.1.8-beta`; альфа-ветка и альфа-APK не изменялись.

## Поведение

- JSON и форма используют текущую модель ноды. Поддерживаемые скрытые
  XHTTP/Hysteria2-параметры сохраняются после перехода в форму.
- Изменения входной и выходной ноды применяются немедленно, если включено
  переподключение при изменении настроек. Иначе — при следующем подключении.
- Изменение подключения сбрасывает результат ноды. Ответы старой конфигурации
  отбрасываются по идентификатору запроса, поколению проверки и версии ноды.
- «Дополнительные TLS-отпечатки» выключены по умолчанию. Настройка добавляет
  Safari 16.0, Chrome 120 и iOS 14 в общий список создания и редактирования.
  Сохранённые и импортированные значения остаются доступны своей ноде.
- Auto сохраняет прежнее поведение. Старые профили могут уменьшить ClientHello,
  но это не гарантирует ускорение или экономию энергии.
- Старые сохранённые TCP-пинги сбрасываются при миграции.

## URL-тест

Стандартный адрес: `http://cp.cloudflare.com/`, ожидаемый статус — 204.
Для пользовательского полного HTTP/HTTPS URL успехом считается 2xx.
Перенаправления и ошибки никогда не заменяются успешным TCP-пингом.
Недоступность сайта тоже может приводить к ошибке теста.

Каждая нода проверяется самостоятельно в процессе `:probe`. Применяются
credentials, транспорт, fingerprint и общие настройки outbound. Правила
обхода и выбранная цепочка не участвуют в массовой проверке. Xray использует
единственный HTTP inbound на свободном loopback-порту; Hysteria2/Naive —
аналогичный самостоятельный libbox-конфиг. Ядра не обновлены.

Один прогревочный GET и один измеряемый GET используют тот же экземпляр ядра.
На запрос отводится 3 секунды, на запуск — 10 секунд. Одновременно работают
не более двух ядер, libbox — не более одного. Пробы имеют отдельные каталоги,
не открывают TUN и не меняют underlying networks активного VPN. Отмена из UI,
закрытие Activity и ошибки освобождают ресурсы. Остаточные временные каталоги
после завершения процесса ОС удаляются при следующем запуске сервиса.

Пинг активного подключения отображается отдельно и идёт через действующий
HTTP proxy runtime, включая фактическую цепочку. На неподдерживаемой платформе
URL-тест возвращает N/A.

## Выбор диагностики

На главном экране рядом со сканированием доступен выбор TCP/URL.
Этот же выбор расположен в «Настройки → Приложение → Ноды» и сохраняется
после перезапуска; по умолчанию выбран URL. При смене режима результаты
списка сбрасываются, запоздавшие ответы прежнего режима отбрасываются.
TCP использует сохранённый адрес диагностики или адрес/порт самой ноды.

В настройках отдельно доступны «Диагностика TCP» и «Диагностика URL»
с выбором ноды. Они работают независимо от режима главного экрана.
«Диагностика в меню ноды» выключена по умолчанию. При включении меню
обычной ноды и избранного предлагает противоположный тест: URL при TCP
по умолчанию и TCP при URL. Результат показывается в отдельном диалоге
и не перезаписывает пинг списка. Изменение URL не сбрасывает готовые
TCP-результаты, изменение TCP-адреса не сбрасывает готовые URL-результаты.

## Автоматические проверки

- `flutter analyze --no-pub`
- `flutter test --no-pub`
- JDK 17: `android/gradlew.bat :app:testDebugUnitTest :app:assembleDebug`

Последний полный прогон: 293 Flutter-теста и 122 Kotlin-теста прошли;
Flutter-анализ без замечаний, стандартный debug APK собран. Один существующий
тест с исполняемым Xray пропущен из-за отсутствия `XRAY_TEST_BINARY`.

Добавлены проверки JSON → форма → сохранение → повторное открытие → экспорт;
изменения общих полей всех шести VLESS-транспортов; скрытых полей XHTTP,
Hysteria2 и Naive; TLS/REALITY fingerprint; настройки дополнительных профилей;
двух параллельных проб; обеих нод цепочки с автопереподключением и без него;
сброса пинга, отмены, устаревших ответов и неподдерживаемого канала.
Локальные HTTP-прокси проверяют 204/200/301/407/502, отсутствие редиректов,
авторизацию runtime, два GET и таймаут незавершённого тела ответа.
Дополнительно проверены сохранение режима и переключателя меню после
перезапуска; TCP-сканирование локального порта без вызова URL-канала;
независимость разовых TCP/URL-проверок от пинга списка; смена режима во
время незавершённой пробы; оба варианта и отключение пункта меню;
работа URL-инструмента в настройках при TCP по умолчанию.

Существующий тест с настоящим Xray (`xray_core_xhttp_integration_test.dart`)
требует `XRAY_TEST_BINARY` для версии 26.7.28 и пропускается без него.

## Проверка на устройстве — не выполнена

В рабочем окружении `adb devices -l` не показывает подключённых устройств.
Unit-тесты и сборка не подтверждают работу реальных соединений на Android.
Для окончательной приёмки необходимо повторить следующую матрицу на устройстве:

| Режим | Проверки |
|---|---|
| VPN выключен | Рабочая VLESS и UDP Hysteria2; открытый TCP-порт с неверными credentials; ошибочные SNI и REALITY |
| libbox TUN | Массовый тест не прерывает текущий VPN; активный пинг отражает действующий туннель |
| Xray TUN | Те же проверки, собственные порты и конфиг VPN остаются прежними |
| Proxy-only | Массовые пробы независимы; активный пинг работает с HTTP proxy auth и без него |
| Активная цепочка | Массово проверяется каждая нода отдельно; активный пинг проходит оба звена; изменение обоих звеньев проверяется с автопереподключением и без него |

Во всех режимах проверить таймаут, redirect, отказ сайта, отмену, закрытие
Activity, редактирование во время проверки, отсутствие оставшихся процессов
и временных конфигов. Проверить сохранение переключателя отпечатков после
перезапуска и сохранность уже выбранного профиля при его отключении.
